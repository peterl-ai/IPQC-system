Runtime DI wraps an explicitly configured isolated original issuer in cleanup-only mode; both adapter and processor prohibit new Issue. Production has no configured signer and cannot load the development issuer.

## Original-operation cleanup and custody

Do not deploy automatically or run cleanup against production based on this document. For a later approved rollout, first stop every old signing-capable instance/worker and inventory its outstanding operations. Retain original environment IDs, CA/key custody, durable public journal and revocation tombstones. Never create a new CA/journal or new operation ID to complete an old obligation. Rolling back to an old signing build can reopen retired operations and is not a safe operational rollback.

Configuration:

- `Enrollment__CleanupEnabled=false` by default. Explicit true permits only bounded closure/recovery/revocation for the original configured environment.
- `Enrollment__WorkerEnabled=false` stops automatic scheduling; it never enables issuance. Direct scoped processor execution still requires CleanupEnabled. No new public processing API was added.
- Keep `Enrollment__EnvironmentId` equal to the original record environment for cancellation and cleanup. Wrong environment cannot rewrite records or obtain cleanup acknowledgement.
- Only the pre-existing isolated Development/Testing issuer can be selected using `DevelopmentIssuerEnabled` together with explicit cleanup opt-in, original `RootPfxPath`/`RootPassword` and `ReceiptDirectory` outside Git. The original journal directory must exist. This is not a production CA adapter or production revocation service. No keys are generated by application startup.
- Invalid/missing original signer material produces an unavailable adapter and deferred cleanup. A missing operation receipt without an existing acknowledged revocation tombstone yields Unknown in the runtime cleanup adapter, not proof of non-issuance. It cannot create a success tombstone for that missing result. Preserve pending and reconcile with IT.

The processor selects actual persisted open requests (including no-candidate, projected-expired and issued-unconfirmed) and pending failed/revoked/unknown credentials, respecting leases. It uses existing Cancelled/Expired transitions with System audit, consumes outstanding challenges, preserves immutable IDs/versions/approval/public certificate facts and does not clear the registry reservation. Existing `CloseAsync` OR-preserves unresolved pending flags, including Failed plus CertificatePem=null.

External Recover/Revoke run after the claim transaction commits. Issuer ID/root must match the original candidate. Unknown defers; definitive NotIssued never leads to Issue and still requires an acknowledged cancellation/revocation fence. Original public result/journal remains intact; existing credential metadata is not replaced by a new certificate. Only durable signer acknowledgement followed by the matching lease/identity check and atomic result-audit commit clears pending. A failed commit repeats the same idempotent operation after lease expiry. Network calls can repeat; the committed acknowledgement audit must not duplicate. Older workers cannot finalize a new worker's lease. Null/old due times precede retried work, avoiding starvation beyond the eight-per-tick limit.
